# 0001. 아키텍처 결정을 ADR로 기록한다

## 상태
승인됨 · 2026-07-25

## 배경
결정한 이유가 코드에도 커밋에도 충분히 남지 않는다.
특히 "검토했지만 하지 않기로 한 것"은 코드에 흔적이 전혀 없어,
시간이 지나면 이미 기각한 방향을 다시 제안하고 같은 논의를 반복하게 된다.

## 결정
되돌리기 비싼 기술 결정은 `docs/adr/`에 번호를 붙인 마크다운으로 남긴다.
한 번 작성한 ADR의 본문은 고치지 않고, 결정이 바뀌면 새 번호로 추가한 뒤
기존 ADR의 상태 줄만 `대체됨`으로 바꾼다.

## 고려했으나 안 한 것
- 커밋 메시지에만 남기기 → 로그를 전부 뒤져야 해서 실질적으로 참조되지 않는다
- 기능 문서(`docs/*.md`)에 함께 적기 → 기능이 끝나면 죽는 문서라 결정이 같이 묻힌다

## 결과
- 좋아진 점: 결정 이유와 기각한 대안이 보존된다
- 나빠진 점: 결정할 때마다 문서를 하나 더 써야 한다
- 대상은 "되돌리기 비싼 결정"으로 한정한다 (오타·색상·문구는 대상이 아니다)
